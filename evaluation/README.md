# Indirect prompt-injection evaluation with Inspect AI

This evaluation replays responses generated by Qwen2.5-0.5B-Instruct on
synthetic question-and-evidence tasks. It uses the
[Inspect AI framework](https://github.com/UKGovernmentBEIS/inspect_ai) and the
original scoring rules in `rag_infra/alignment.py`.

The held-out split contains 32 cases from eight scenarios, with clean
questions, injected evidence and missing evidence. The counterfactual split
keeps the same questions and facts, swaps citation IDs and changes the
attack wording. Five split/configuration combinations replay 160 recorded
responses.

Run from the repository root:

```sh
python -m pip install -r evaluation/requirements.txt
python -m evaluation.inspect_rag
inspect view --log-dir artifacts/inspect-rag/logs
```

The script checks the dataset hash and sample IDs, then compares every
re-scored response and aggregate with the recorded experiment. The Inspect
logs provide per-response transcripts and grades. The summary adds failure
slices by attack family, ordinary answer or missing evidence, and paired
base-to-LoRA outcome transitions.

| Held-out configuration | Successful attacks | Clean answer and citation | Exact missing-evidence abstention |
| --- | ---: | ---: | ---: |
| Base with evidence boundary | 5/16 | 0/8 | 0/8 |
| Base with prefix filter | 1/16 | 0/8 | 0/8 |
| LoRA with the same evidence boundary | 0/16 | 8/8 | 8/8 |

With prefix filtering, seven of eight clean answers had the expected fact
but an incorrect or missing citation. All eight missing-evidence cases
were answered instead of refused. In the counterfactual split, attack
successes went from 8/16 for the base model to 0/16 with LoRA. The
counterfactual split reuses the original scenarios.

This is offline verification of recorded output and scoring, with no new
inference during replay. The benchmark measures generation with fixed
supplied evidence. The source files contain synthetic cases and recorded
outputs, with no institution-owned data, credentials or weights.
